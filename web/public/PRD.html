1摘要

LetThemKnow 讓每個租戶用自己的 SMTP 與 LINE 官方帳號，對自己的名單發送通知。平台負責名單管理、範本、排程、分批發送、失敗重試與結果追蹤；憑證與發送信譽留在租戶自己手上。

租戶除了使用網頁主控台，也可以用 API key 讓自家系統（例如 ERP、訂單系統）直接觸發單筆通知，不需要人工操作。

v1 已完成開發、測試並正式上線。本文件描述的功能皆為已實作且可驗證的內容，所有數值取自程式碼或實測，非估計值。

2問題與背景

企業要發送交易通知或行銷訊息時，通常面臨三個問題。

  • 工具各自為政。Email 用一套系統、LINE 用另一套，名單與發送結果無法放在一起看。
  • 發送信譽綁在第三方。多數 SaaS 用自己的伺服器代發，一旦其他客戶被檢舉，你的信件也一起被擋。
  • 系統要串接很麻煩。訂單成立要即時通知客戶時，行銷工具往往只提供批次匯入，無法由程式即時觸發。

LetThemKnow 的取捨是：平台不碰發送憑證的所有權。每個租戶填入自己的 SMTP 帳號與 LINE Channel access token，平台只負責排程與派送。信譽、退信、同意權都留在租戶身上，平台不會成為共用的黑名單來源。

同時，平台把「批次活動」與「單筆即時通知」放在同一套範本與紀錄之下，行銷人員在主控台編輯的範本，工程師可以直接用 API 呼叫。

3目標與非目標

目標

  • 讓非技術人員在主控台完成「建立範本 → 匯入名單 → 發送 → 查看結果」的完整流程。
  • 租戶之間的資料完全隔離，任何情況下都不會互相看見。
  • 通道憑證加密儲存，介面與 API 一律不回傳明文。
  • 發送過程可中止、可重試，失敗名單可以被人工檢視與處理。
  • 提供外部系統以 API key 觸發單筆通知的介面。
  • 在單一小型主機上穩定運作，控制營運成本。

非目標（v1 明確不做）

以下項目經評估後排除，不是遺漏。列在這裡是為了讓審查時有明確的討論對象。

  • Refresh token 與多角色權限（v1 僅有 ADMIN 一種角色）
  • LINE 接收訊息的 webhook（僅單向發送）
  • 退訂與抑制名單（suppression list）
  • 各租戶的 SMTP 發送速率節流
  • 介面多語系
  • Worker 獨立部署（v1 與 API 同一個程序）
  • 加密金鑰輪替機制

5功能範圍

5.1　帳號與租戶

使用者可在 /signup 以「公司名稱、Email、密碼、註冊碼」建立自己的工作空間，成功後直接登入，不需要再登入一次。登入後取得的憑證有效 12 小時。

註冊碼未設定時，自助註冊是關閉的，而不是開放的。管理者必須主動設定註冊碼才會開放。輸入錯誤的註冊碼與「功能未開放」會得到完全相同的回應，外界無法藉此探測。

5.2　訊息範本

提供 9 組現成範本：Email 6 組（公告、訂單更新、歡迎信、簡要通知、收據、安全提醒），LINE 3 組（文字公告、按鈕卡片、訂單 Flex 卡片）。編輯時右側即時預覽，Email 可切換桌機與手機寬度。

內容以 {{參數}} 代入收件人資料。Email 範本全部使用表格排版與行內樣式，不含任何圖片檔，因為 Gmail 與 Outlook 會移除 SVG。

5.3　名單匯入

以 CSV 上傳，第一欄為收件人（Email 或 LINE user ID），其餘欄位成為範本參數。上傳區提供「下載範例 CSV」，欄位會依照該活動所選範本的參數自動產生，不會對不上。

項目規則
檔案大小最大 20 MB
筆數最多 200,000 筆
重複收件人自動去除，只保留一筆
Email 格式必須符合基本 Email 格式，否則略過
LINE user ID必須為 U 開頭加 32 碼小寫十六進位
可匯入時機僅限草稿狀態的活動

5.4　通道設定

Email 填入 SMTP 主機、埠、加密方式、帳號密碼與寄件人。儲存前會實際寄出一封測試信，寄不出去就不會儲存，所以儲存成功代表真的能寄信，而不是設定看起來正確。

LINE 填入 Channel secret 與 access token。兩者的密碼與 token 都經過加密後才寫入資料庫。

5.5　活動發送

活動可立即發送或指定時間發送。系統將名單切成小批處理：Email 每批 50 筆，LINE 每批 500 筆（LINE multicast 的上限）。每筆收件人各自記錄狀態，因此可以精確知道誰收到、誰沒收到。

5.6　失敗處理與重試

系統區分兩種失敗。暫時性失敗（連線逾時、對方限流）自動重試最多 3 次，間隔 30 秒起逐次加倍；永久性失敗（地址無效、憑證錯誤）直接標記失敗，不浪費重試次數。

活動結束後若有失敗，狀態會停在 AWAITING_RESOLUTION，等待人工決定。操作者可以檢視失敗清單與原因，再決定是否重送。

5.7　整合 API

租戶可自行產生 API key，讓自家系統呼叫。金鑰明文只在建立當下顯示一次，之後系統只留雜湊值。

用途說明
連線測試確認金鑰有效
發送單筆指定範本與收件人，同步送出並回傳結果
查詢紀錄以訊息編號查詢該筆的發送狀態

限流：每把金鑰每分鐘 60 次，超過回應 429 並附上重試秒數。請注意部分 HTTP 客戶端（例如 Apache HttpClient 5）會自動遵守該標頭並靜默重送，讓程式看不到被限流。

5.8　主控台

頁面包含儀表板、活動列表與四步驟建立精靈、活動明細（即時計數與失敗處理抽屜）、範本編輯器、通道設定、API 金鑰，以及給整合工程師的開發者頁面，內含可直接複製的 curl／Node／Python 範例。時間一律以台北時間顯示，資料庫則統一存 UTC。

6活動生命週期

活動的狀態轉換是系統的核心規則，所有操作都必須遵循。不合法的轉換會被拒絕。

DRAFT → SCHEDULED → PROCESSING → COMPLETED AWAITING_RESOLUTION
AWAITING_RESOLUTION → RETRYING → COMPLETED AWAITING_RESOLUTION
任何進行中狀態 → TERMINATED （人工中止）

完成規則：失敗數為 0 則進入 COMPLETED，只要有任何一筆失敗就進入 AWAITING_RESOLUTION，交由人判斷。系統不會自作主張地把有失敗的活動標記為完成。

收件人狀態

每一位收件人各自有狀態，活動的統計數字由這些狀態累加而成。

狀態意義
PENDING已匯入，尚未送出
SENDING已被取走，正在送出
SENT已成功送出
FAILED送出失敗，重試次數已用盡或屬永久性錯誤
CANCELLED活動被中止，這筆未送出

不重複發送：派送前系統會先鎖定該批收件人，只有實際鎖到的才會送出。即使處理過程中途中斷，已送出的收件人也不會被重送；未完成的批次會在 5 分鐘後由回收機制接手。

7安全與資料保護

租戶隔離

每一筆與租戶相關的資料都帶有租戶識別，查詢時由系統自動加上條件，不依賴開發者記得手動過濾。

存取其他租戶的資料時，系統回應「找不到」而不是「沒有權限」。這是刻意的設計：回應「沒有權限」等於承認該筆資料存在，可被用來推測其他租戶的規模與活動。

憑證保護

  • SMTP 密碼與 LINE token 以 AES-256-GCM 加密後儲存。
  • API 回應只顯示「是否已設定」，不回傳明文，也不回傳遮罩後可還原的內容。
  • 系統紀錄中不會出現解密後的值。
  • API key 只保存雜湊值，比對採用固定時間演算法，避免由回應時間推測金鑰。

存取控制

使用者驗證方式可存取範圍
主控台使用者登入後取得的憑證，效期 12 小時該租戶的全部功能
外部系統X-API-KEY僅整合 API，不能存取主控台功能

金鑰遺失的後果：主加密金鑰用來解開所有租戶的通道憑證。金鑰一旦遺失，資料庫備份中的憑證將無法還原，所有租戶必須重新輸入。此金鑰必須與備份分開保存。

9部署與營運

系統執行於單一台 Google Cloud 小型主機，前方以 Cloudflare Tunnel 承接流量。

對外沒有開放任何網頁連接埠

主機上的通道程式主動向 Cloudflare 建立連線，流量從這條連線回來，因此不需要開放 HTTP 埠，也沒有對外的網頁服務可被掃描攻擊。唯一對外開放的是 SSH，僅供自動部署使用，且只接受金鑰。

自動部署

程式碼推送後自動建置映像檔、上傳、連線到主機更新服務，並等待服務回報健康才算成功。因此部署結果是紅燈時，代表服務真的沒起來，而不只是連線失敗。

成本

項目費用說明
主機US$0符合免費額度
硬碟US$0符合免費額度
對外 IP≈ US$3.65 / 月依使用時數計費，無免費額度

對外 IP 是本架構唯一無法避免的固定費用。主機本身免費，但它的對外位址不是。此外每月有 1 GB 的對外流量額度，主控台使用量大時需留意。

備份

所有重要資料都在資料庫中：租戶、範本、活動與加密後的通道憑證。備份指令已寫入維運手冊。備份本身無法單獨還原，必須搭配主加密金鑰，因此兩者要分開保存。

11後續規劃

依價值與風險排序，非承諾時程。

產品功能

  • 退訂與抑制名單　對行銷用途而言，這是最接近法規要求的缺口，建議優先。
  • 細分角色權限　目前一個租戶內所有人權限相同，不利於多人協作。
  • LINE 接收訊息　可承接客戶回覆，將單向通知擴展為雙向溝通。
  • 介面多語系　目前僅有單一語言介面。

營運改善

  • 縮短啟動時間　目前啟動約需 6 分鐘，主因是主機記憶體不足而頻繁置換。實測顯示約有 130 MB 被與本系統無關的監控代理程式佔用，移除後可望明顯改善。
  • 改用保留 IP　費用與現況相同，但可避免主機重啟後位址變動導致部署失敗。
  • 備份自動化　目前為手動指令，建議排程並將備份送出主機外。
  • 金鑰輪替　目前主加密金鑰無法在不重新輸入憑證的情況下更換。
